Frequently Asked Questions

How often is the data updated?

The dashboard updates in real-time, with new sensor readings being fetched every second. This ensures you always have the most current flood monitoring data.

What do the warning states mean?

State 0 (Green): Normal conditions - water level below the warning threshold
State 1 (Yellow): Warning level - water level between the thresholds
State 2 (Red): Critical level - water level above the critical threshold

How can I customize the dashboard?

The dashboard has locally stored settings for each user. This allows for customization for any user. These settings include: Refresh Rate, Distance Unit, Threshold Levels, Alarm Settings, and Heartbeat Settings.

Please note that the Threshold Levels are dashboard-side only — they will not affect the levels on the RIPPLE system.

How accurate are the sensor readings?

Our sensors are calibrated to provide accuracy within ±0.1 inches. They are regularly maintained and tested to ensure reliable flood monitoring data.

What should I do if I see a critical warning?

If you see a critical (red) warning, follow your organization's emergency flood response procedures immediately.

Can I access historical data?

Yes! Use the duration selector in the graph card to view data from the past 3 hours up to 1 week. Historical data can help identify patterns and trends.

What does the "Time to Flood" estimate mean?

This is a predictive estimate based on the current rate of water level change. It indicates how much time you have before flooding conditions are expected to occur if the current trend continues. Although this isn't a reliable way to detect the flooding of a particular area, it is only supposed to be an estimate.

How do I request new images?

Click the "Request Images" button in the Live View card. The system will capture fresh images from all monitoring cameras and display them within a few seconds.

What is the Heartbeat and what does it do?

The Heartbeat is an automatic background health check that runs on a configurable interval (default: 45 seconds). It silently checks whether the MySQL database and MQTT broker are reachable, then reads the latest pole status from the database and updates the status indicators on the dashboard.

Important: The Heartbeat only reads from the database — it never sends any request to the physical sensor poles. To actively contact the poles and get an immediate live response, use the Ping Sensors button instead.

The Heartbeat can be enabled or disabled and its interval adjusted from the Settings page under Heartbeat Settings. Disabling it is useful if you want to reduce background network traffic, but the status indicators will no longer update automatically.

What is the difference between the Heartbeat and the Ping Sensors button?

These two features serve different purposes:

Heartbeat (automatic): Runs quietly in the background on a timer. It only queries the database for the last recorded pole status — no signal is ever sent to the hardware poles. This is the normal way the dashboard keeps its status indicators current.

Ping Sensors (manual): Triggered only when you click the button. It sends an active MQTT request directly to the sensor poles and waits up to 45 seconds for them to respond. Use this when you want to confirm in real time that the poles are alive and communicating, or after a suspected outage.

What is the Debug Console on the Settings page?

The Debug Console is an on-page log viewer intended for troubleshooting. It captures all internal messages generated by the dashboard — including data poll results, connection status changes, image requests, and any errors — and displays them in a scrollable panel at the bottom of the Settings page.

You can filter messages by severity using the Log Level dropdown:
All (Info + Warn + Error): Shows every message, including routine operational logs.
Warn + Error: Shows only warnings and errors — useful for spotting problems without the noise.
Error Only: Shows only errors — the default, recommended for day-to-day use.

The Copy button copies all currently visible log entries to your clipboard so they can be pasted into a support request or shared with your system administrator. The Clear button wipes the log. The console can be collapsed with the Hide/Show Console button and will remember its collapsed state between visits.

The Ping or Request Images button is stuck and won't work. What do I do?

Both action buttons are automatically disabled while a request is in flight to prevent duplicate requests from being sent. In rare cases — such as a network timeout or navigating away mid-request — a button can get stuck in the disabled state even though the request has already finished.

To fix this, go to the Settings page and scroll down to Action Button Reset. Click Reset Button Locks to immediately re-enable both buttons. This is safe to use at any time — it simply clears the lock without affecting any data or active connections.
