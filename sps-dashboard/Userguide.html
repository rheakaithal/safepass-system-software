1 Dashboard Overview

The RIPPLE dashboard is a real-time flood monitoring interface built by Safe Pass Systems for Texas A&M University. It reads water level data from physical sensor poles in the field, displays live readings and historical trends, and raises visual and audio alarms when water levels reach dangerous thresholds.

🏠 Home
Overview of all monitoring locations with at-a-glance status cards. Your starting point.
📊 Location Dashboard
Detailed live data for a specific location - pole status, images, chart, and ping controls.
⚙️ Settings
Per-user preferences stored locally - units, thresholds, alarm volume, heartbeat interval, and more.
❓ FAQ
Quick answers to common questions about the dashboard's features and behaviour.

All pages load inside a central content frame managed by the sidebar navigation. Clicking any sidebar link updates the content area without reloading the entire page. Your settings are saved to your browser's local storage and persist across sessions.

2 Home Page & Location Cards

The Home page is the dashboard's landing screen. It shows one card per configured monitoring location, each displaying live sensor readings and an overall status badge. Cards refresh automatically every 5 seconds.

Location card status colors

The colored bar at the top of each card and the badge in the top-right corner both reflect the worst state across all poles at that location:

Normal All poles below the warning threshold.
Warning At least one pole is between the warning and critical thresholds.
Critical At least one pole has reached or exceeded the critical threshold.
Offline The server could not be reached.

Navigating to a location dashboard

Click anywhere on a location card to open its full dashboard. You can also use the sidebar links under the Dashboards section to navigate directly.

3 Pole Status Card

The Pole Status card is the primary real-time readout for a location. It shows the current water level, warning state icon, and an estimated time-to-flood for each sensor pole.

Water level badge

Each pole row displays its current water level with a colored badge. If the level is below 1 inch, the badge reads "Less Than 1 [unit]" to indicate a near-dry reading. The unit (inches or centimetres) follows your preference set in Settings.

Warning state icons

The icon on the right of each pole row changes based on the current water level:

Green icon (State 0): Water is below the warning threshold. Conditions are normal.
Yellow icon (State 1): Water is between the warning and critical thresholds. Monitor closely.
Red icon (State 2): Water has reached or exceeded the critical threshold. Take action immediately.

Est. Time to Flood

Below each pole name, the dashboard displays a predicted time until the water level reaches the critical threshold. This estimate is calculated from the rate of change over the last 10 sensor readings.

⚠️ The time-to-flood estimate is a rough trend projection, not a guaranteed forecast. It is only shown when the water is actively rising and the predicted time is within 2 hours. Values under 10 minutes are highlighted in red and pulse to draw attention.

If the row displays "FLOODING NOW" in red, the pole has already reached the critical threshold and the continuous alarm will be active.

4 Ping Sensors

The Ping card lets you actively verify that the sensor poles, MQTT broker, and MySQL database are all reachable. Two separate mechanisms keep the status indicators updated:

Automatic Heartbeat (background)

The heartbeat runs silently on a configurable timer (default: 45 seconds). It checks MySQL and MQTT connectivity, then reads the most recently recorded pole status from the database. It never sends any request to the physical poles - it only reads existing data. The interval and on/off state can be configured in Settings.

Ping Sensors button (manual)

Clicking Ping Sensors triggers an active MQTT message to the poles and waits up to 45 seconds for a response. Use this when you need to confirm in real time that the hardware is alive, or to diagnose a suspected outage.

1
Click Ping Sensors. Both action buttons will grey out while the request is active.
2
The status indicators switch to Checking… while awaiting a response.
3
After up to 45 seconds, the indicators update to reflect the live pole response.
4
Buttons are re-enabled automatically once the ping completes or times out.
Status indicator states

● Online - All systems and poles responding.
● Degraded - One or more components are not responding (see the label for detail).
● Offline - Core systems (MySQL or MQTT) are unreachable.
● Checking - A ping is currently in progress.

ℹ️ If the Ping button stays greyed out after a request finishes, go to Settings → Action Button Reset and click Reset Button Locks to manually re-enable it.
5 Live Images

The System Images card shows photos from the cameras mounted at the monitoring location. Three views are available via the selector buttons at the bottom of the card: Location (overview), Pole 1, and Pole 2.

Requesting new images
1
Click Request Images in the card header. A Requesting… badge appears.
2
The server publishes an MQTT request to the RIPPLE system. The poles capture images and write them to the database.
3
Once the database signals completion, the server reads the images and returns them to the dashboard.
4
Images are saved to disk on the server and displayed in the viewer. The badge shows Images Updated on success.
ℹ️ The full image request can take up to 6 minutes. Both action buttons remain disabled for the duration. On reload, the most recently captured images are loaded automatically - no new request is needed.
Status badges

Requesting… - Request is active.
Images Updated - New images were successfully captured and saved.
Request Failed / Timed Out - The request did not complete. Check system connectivity and try again.

6 Water Level History Chart

The chart plots water level readings over time for both poles. Data is loaded from the last 8 days of records on startup, then updated on every live data poll. Timestamps between poles are unified through linear interpolation so both lines share the same time axis even if the poles report at slightly different rates.

Duration selector

Use the Duration dropdown in the chart header to change the visible time window: 3 Hours, 12 Hours (default), 1 Day, 3 Days, or 1 Week. The time axis ticks snap to clean boundaries (e.g. whole hours) for readability.

Pole selector

Use the Poles dropdown to show all poles, Pole 1 only, or Pole 2 only. Hidden poles are also hidden from the hover readout panel.

Hover crosshair & readout

Moving your cursor over the chart draws a vertical crosshair and populates the readout panel in the card header with the timestamp and exact water level for both poles at that point. The readout respects your current distance unit setting.

7 Alarms & Visual Alerts

When any pole reaches the critical threshold the dashboard activates two simultaneous alerts to ensure the situation is noticed.

Audio alarm

A two-tone siren (alternating 800 Hz / 1000 Hz) plays on a 3-second loop for as long as critical flooding is detected. Volume is set in Settings. The alarm stops automatically when all poles fall back below the critical threshold.

🔴 The alarm only triggers on the transition from non-flooding to flooding, not on every data poll tick. If you reload the page during an active flood event, the alarm will restart once the first data poll confirms that a pole is still above the critical threshold.
Border pulse

A pulsing red border appears around the entire page body whenever critical flooding is active. This provides a persistent full-screen visual cue even if the audio is muted or the volume is turned down.

Disabling the alarm

Navigate to Settings → Alarm Settings and uncheck Enable Critical Flood Alarm. The border pulse will remain active as a silent visual-only alert. You can also reduce the alarm volume with the slider and test it with the Test Alarm button before saving.

8 Settings

All settings are stored in your browser's local storage. Changes do not affect any other user or the physical RIPPLE hardware. Click Save Settings to apply; the button flashes green on success or red if a value failed validation.

Setting Description Default
Update Frequency How often the dashboard polls the server for new water level data. 1 second
Distance Units Display units for all water level readings. Switching units converts existing values and chart axis labels immediately. Inches
Warning Level Water level at which poles enter the yellow warning state. Must be lower than the critical level. Dashboard-side only - does not affect the hardware. 3.0 in
Critical Level Water level at which poles enter the red critical state and the alarm triggers. Dashboard-side only - does not affect the hardware. 6.0 in
Enable Alarm Enables or disables the audio alarm on critical flood detection. The visual border pulse always remains active. On
Alarm Volume Volume of the alarm tone from 0% (silent) to 100% (maximum). Use the Test Alarm button to preview. 70%
Enable Heartbeat Enables the automatic background health check. When disabled, status indicators only update when Ping Sensors is clicked manually. On
Heartbeat Interval How often the background health check runs. Lower values give faster status updates but increase server load. 45 seconds
Action Button Reset

If the Ping Sensors or Request Images button becomes stuck in the disabled state after a timeout, click Reset Button Locks to re-enable both immediately. This is safe to use at any time.

9 Debug Console

The Debug Console appears at the bottom of the Settings page. It captures all internal log messages produced by the dashboard - data polls, connection events, image requests, alarm transitions, and errors - in a scrollable panel. Log messages persist across page navigation for the duration of your browser session.

Log levels

Use the Log Level dropdown to filter what's shown:

All (Info + Warn + Error) - Every message, including routine operational logs. Useful when investigating unexpected behaviour.
Warn + Error - Only warnings and errors. Good for spotting intermittent issues without the noise of normal poll logs.
Error Only - Only hard errors. The recommended default for day-to-day monitoring.

Controls

Copy - Copies all visible log entries to your clipboard as plain text, formatted with timestamps and log levels. Useful for sharing with support.
Clear - Wipes the log buffer. New messages continue to be captured after clearing.
Hide / Show Console - Collapses or expands the panel. The collapsed state is remembered between visits.

ℹ️ When contacting Safe Pass Systems for technical support, set the Log Level to All, reproduce the issue, then use Copy to include the full log in your message. This gives the support team the context needed to diagnose the problem quickly.
10 Troubleshooting
Status shows "Offline" or "Degraded"

Check that the server running the RIPPLE backend is online. If MySQL or MQTT shows as unreachable, contact your system administrator. The status label in the indicator gives the specific component that is failing (e.g. "MySQL Unreachable" or "Main Pole Unreachable").

Chart shows no data or a flat line

Confirm the server is reachable and that the selected duration window contains recorded data. On first deployment or after a database reset, historical records will not exist yet and the chart will be empty until new readings arrive.

Alarm keeps sounding even though levels look normal

Check that your Warning and Critical threshold settings match the values intended for this deployment. Settings are stored locally and may differ from what other users see. Reload the page. If a pole is truly above the critical threshold the alarm will restart after the first data poll.

Ping or Image Request button is greyed out and won't respond

Go to Settings → Action Button Reset → Reset Button Locks. See Section 8 for details.

Images are not updating after requesting

Image capture can take up to 6 minutes. If the badge shows Timed Out or Request Failed, verify that the RIPPLE hardware and MQTT broker are online using the Ping Sensors button. If the ping succeeds but image requests continue to fail, contact your system administrator.

Settings don't appear to save

If the Save Settings button flashes red, one of the threshold inputs contains an invalid value (blank or non-numeric). Correct the value and try again. If your browser has local storage disabled or in private/incognito mode, settings will not persist between sessions.

ℹ️ For issues not covered here, contact Safe Pass Systems at SafePassSystems@gmail.com. Please include a copy of the Debug Console log (Settings → Debug Console → Copy) with your message.
